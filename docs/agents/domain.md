# Domain docs

Dieses Repository verwendet ein Single-context-Layout:

- `GLOSSARY.md` im Repository-Hauptverzeichnis
- Architekturentscheidungen unter `docs/adr/`

Vor Code-Erkundungen das Glossar und thematisch relevante ADRs lesen.
Fehlende Dateien still überspringen. Erst bei tatsächlich geklärten
Begriffen oder Entscheidungen durch Domain Modeling anlegen.

In Issues, Vorschlägen und Tests die Begriffe des Glossars verwenden.
Fehlende Begriffe als mögliche Lücke behandeln, nicht als bereits
beschlossene Terminologie.

Widersprüche zu bestehenden ADRs ausdrücklich benennen und begründen.
Die lokalen Projektanweisungen und das Projektgedächtnis zusätzlich
beachten; diese Dokumente ersetzen sie nicht.
